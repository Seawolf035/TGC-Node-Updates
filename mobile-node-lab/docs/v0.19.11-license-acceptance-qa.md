# v0.19.11 Quest/phone license acceptance regression checklist

Scope: first-launch license UI only. No legal text revision, installer data wipe, or network/relay code change. Patch code 63, package `club.thegamerclub.nodelab`, signature must match code 62.

## Manual headset/phone checks (required before claiming hardware validation)
1. On a Quest 2 and Quest 3 with v0.19.10 installed and staff link, local favorites, OSC settings, permissions and tracking preferences present, **do not uninstall or clear storage**. Install the *stable-key signed* v0.19.11 APK as an update. Confirm previously stored app data survives.
2. If agreement `2026-10-13.1` was not yet accepted: open the app, scroll the agreement using Quest controller pointer and/or touch, and confirm the bottom **Decline & Exit** and **Agree & Continue** controls remain visible and clickable at every scroll position.
3. Tap **Agree & Continue** once. Confirm the normal Companion home appears without a prompt loop, then switch tabs, open Quest Tools, leave and reopen the app. Consent remains accepted. No automatic agreement acceptance happens merely from entering or scrolling this page.
4. For a controlled fresh install/test profile, verify the first-launch agreement is shown and acceptance works. In a separate test, choose **Decline & Exit**; verify the app closes without saving consent, and a subsequent launch still asks. Only do this on a disposable install/profile, never wipe an existing linked staff device.
5. On a phone, repeat first-launch scroll/accept/decline tests, including both landscape and portrait. Check the software keyboard or accessibility text size does not obscure both buttons. Confirm the *phone* floater still exists, but Quest does not get one.
6. If agreement was already accepted in code 62, upgrading to code 63 must **not** require reacceptance: the agreement version and text remain `2026-10-13.1`. Confirm Settings can review it and close the review panel.
7. Main **Tracking** tab must still show the first-use **VRChat → Settings → Debug → Logging → FULL** guide and acknowledgement, with a small **View setup guide** link after acknowledgement. Do not move it to Advanced or trigger a separate full-screen guide.
8. Quest tracking must default to read-only SAF `Documents/Logs` permission and continue reading only appended VRChat log content. Phone tracking must continue requiring Shizuku. Quest Shizuku stays an explicitly chosen fallback under Advanced.
9. Staff authorization must still be checked. Sightings queue/upload may continue, but they do not prove invitations were sent. Relay enrollment and GM3 identification/GM4 eligibility/GM1 invite authority must be unchanged.
10. Inspect Gradle APK output: same `applicationId`, signed certificate equal to code 62, `versionCode=63`. Verify public JSON `version=0.19.11` and published APK SHA256 after official release.

## Automated checks
- Java debug assembly and static consent/architecture assertions: `.github/workflows/mobile-companion-license-qa.yml`.
- Official workflow builds and verifies permanent-signing-key compatibility; it never publishes unsigned debug APK as the stable update.
- The build test is **not a Quest hardware interaction test**. If either Agree click or activity resume still fails on a headset, collect the UI state (unreachable buttons / disabled button / click without navigation / repeated prompt) and Android logcat before additional release changes.
