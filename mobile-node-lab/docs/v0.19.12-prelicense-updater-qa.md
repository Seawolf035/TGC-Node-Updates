# TGC Staff Companion v0.19.12 (code 64): pre-license update recovery

## Design constraints
- A user must be able to check, download, and install an official signed update **before** accepting the currently installed agreement, including when the agreement asset fails to load.
- The updater alone (`MobileUpdaterActivity`) bypasses the application-level agreement gate. It is `android:exported="false"` and does not require TGC staff credentials. Do not widen this exception to account sessions, tracking, Quest Tools, OSC or other services.
- Opening the updater, checking the feed, downloading an APK or completing an installation must **never** imply acceptance. Versioned consent continues to be recorded **only** by explicit Agree & Continue.
- Preserve all SharedPreferences, encrypted device link and local databases. Use the same applicationId and permanent signing key; no uninstall or clear-data instructions.
- Keep the existing trusted GitHub update feed, SHA-256 verification, Android signer/package verification and install permission flow.
- The comprehensive proprietary license rewrite remains separate/unpublished.

## Test matrix
1. **Quest existing install with unaccepted EULA:** Open v0.19.12 and tap **Check for Updates** beneath Agree & Continue and Decline & Exit. Confirm updater loads instead of getting redirected to the license immediately, and checks the real feed. If no newer version exists, it should say up-to-date.
2. **Quest missing agreement asset/error:** Use a disposable instrumented build with an unreadable agreement asset. The error page must still expose **Check for Updates** and **Exit**. The updater loads without granting consent.
3. **Android phone:** Repeat 1 and 2 with touch; confirm Android install permission prompt and app installer can launch while agreement is unaccepted. Signing and SHA checks remain enforced, including rejection of mismatches.
4. **Back/return to agreement:** Press back from the updater. User is returned to the still-unaccepted agreement and cannot reach Home/Tracking/Quest Tools/VRChat account or other protected views until explicit acceptance.
5. **Decline:** Choosing Decline & Exit still exits without recording consent. Relaunch prompts again, but Check for Updates remains available.
6. **Accepted users:** Settings → Check for updates remains unchanged. Settings → Review agreement remains available, and does not require reacceptance of agreement `2026-10-13.1`.
7. **Data-preserving upgrade:** With a genuine signed v0.19.11 APK and existing staff link, favorites, OSC settings and Quest SAF grant, install v0.19.12 directly over it. Check unchanged credentials/preferences/databases and document picker persistence. Do not wipe a real staff device to test first install.
8. **Tracking/network regressions:** Main Tracking inline Logging=FULL guide remains; Quest SAF folder is default with Shizuku only advanced fallback; phone Shizuku still required for live tracking; GM1 remains sole group-invite sender, with Relay and GM3/GM4 authority unchanged.
9. **First run recovery check:** If the updater opens from the license and the update has a bad certificate or hash, do not install it, and return to the agreement with no consent recorded.

## CI vs hardware validation
The automated QA workflow compiles the Android debug APK and runs static source checks. **It cannot validate Quest controller pointer events, install permission UX or a live APK upgrade.** The separate official workflow must validate permanent release key and version bump, publish stable-key signed APK, and update the SHA-256 feed.
